Linux Server Health Monitor

A command-line tool that checks a Linux server's CPU, memory, disks and system details, rates each one OK, WARNING or CRITICAL, and saves every report to a rotating log file. It uses only the Python standard library.

        How it works
        
From /proc files to a report

        
Linux keeps live system numbers in plain text files under /proc. Each collector reads its own files and returns a dictionary. report.py rates the numbers and writes the result.

      

      

        

          
__main__.pyCommand-line options

          
→

          

            
cpu.py/proc/stat · /proc/loadavg

            
memory.py/proc/meminfo

            
disk.pyshutil.disk_usage()

            
sysinfo.py/etc/os-release · /proc/uptime

          

          
→

          
report.pybuild_report() + thresholds

          
→

          

            
ConsoleText or JSON

            
health_report.logRotates at 1 MB, keeps 5

            
Exit code0 / 1 / 2 / 3

          

        

      

      

        

          
CPU usage formula

          
The numbers in /proc/stat are running totals since boot. The tool reads them twice, one second apart, and compares the change.

          
usage % = (1 − Δidle / Δtotal) × 100

          
Idle includes iowait. Example: if 100 units of CPU time passed and 60 were idle, usage is 40%.

        

        

          
Exit codes

          
These follow the Nagios plugin convention, so cron, shell scripts, Jenkins and monitoring systems can react to the result.

          
0 · OK1 · WARNING2 · CRITICAL3 · not Linux

        

      

      

        
Design choices

        
    
          
  • No third-party packages. Libraries like psutil need pip install, which is often blocked on production servers. Reading /proc directly runs anywhere with Python 3.8+.
    • 
          
  • One module per check. CPU, memory, disk and system info are independent, so each can be tested and changed on its own.
    • 
          
  • File paths as parameters. Every function that reads /proc takes the path as an argument, so tests can pass in sample files and run on any OS.
    • 
          
  • Log rotation. RotatingFileHandler caps the log at 1 MB and keeps 5 old files, so a cron job can't fill the disk it is monitoring.
    •

        Try it
        
Run it yourself

        
Paste these into a Linux terminal: a server, WSL, or a GitHub Codespace.

      

      

        
Clone and run once
git clone https://github.com/samuelpremmm/server-health-monitor.git && cd server-health-monitor && python3 -m health_monitor

        
Check two mount points
python3 -m health_monitor --disk / --disk /home

        
Report every 60 seconds (Ctrl+C to stop)
python3 -m health_monitor --watch 60

        
JSON output for other tools
python3 -m health_monitor --json --log-file logs/health.jsonl

        
Stricter CPU limits
python3 -m health_monitor --cpu-warn 60 --cpu-crit 80

        
Run automatically every 5 minutes with cron
bash scripts/install_cron.sh 5

        
Run the tests
pip install pytest && pytest

        
Demo on Windows or macOS with sample data
python scripts/demo_with_fixtures.py
